# MiniPet —— 桌面宠物

一只在桌面上爬来爬去的黑白线稿小虫子。素材来自 `D:\视频素材\蠕动.mp4`。

## 跑起来

```bash
npm install     # 首次
npm start
```

Windows 上也可以直接双击 `start.bat`。

启动后虫子会出现在屏幕下方，自己开始蠕动、发呆、换方向爬。

想启动时直接打开控制选项：`npm start -- --panel`。

> `npm start` 走的是 `tools/launch.js` 而不是直接调 electron，因为这里要处理两件事：
> 清掉环境里残留的 `ELECTRON_RUN_AS_NODE`（否则 Electron 会退化成普通 Node 跑），
> 以及崩溃后自动带 `--no-sandbox` 重试一次（见下方「关于 disableGpu」）。

## 交互

| 操作 | 效果 |
| --- | --- |
| 左键拖动 | 把它拎到任意位置 |
| 左键单击 | 戳它一下，它会朝反方向窜出去 |
| 右键 | 菜单：打开控制选项 / 虫子暂时停止 / 大小 / 速度 / 不透明度 / 开机自启动 / 定时提醒 等 |
| 定时提醒到点 | 虫子在头顶冒出气泡喊出提醒语 |
| 托盘图标单击 | 显示或隐藏 |
| 托盘图标双击 | 打开控制选项 |
| `npm start -- --panel` | 启动并直接打开控制选项 |

虫子的**透明区域是鼠标穿透的**——只有压在虫子身上的那一小块会拦住点击，其余地方该点桌面点桌面，该点别的窗口点别的窗口。

**右键菜单开着的时候是个例外**：菜单是 popup 出来的原生窗口，它的模态循环只接收发给它自己的点击；
穿透窗口会把菜单以外的点击**转发给下面的窗口**，所以菜单收不到「点外面了」的信号，不点虫子本身关不掉。
为此 `popupMenu()` 在弹出前临时 `setIgnoreMouseEvents(false)`，菜单关闭时（`callback` 里）恢复穿透。
菜单本体是宠物窗口的 owned 窗口，Windows 保证 owned 窗口的 z 序恒在其 owner 之上，
所以窗口临时不穿透也不会挡住菜单项——菜单照旧点得动，而窗口其余区域此刻可以正常接点击来关菜单。
渲染进程侧的 `menuOpen` 标志让 hover 高亮和拖拽在菜单开着期间让位，避免互相打架。

## 控制选项

右键菜单第一项「打开控制选项…」、托盘图标双击，或者 `npm start -- --panel` 都能打开。

界面分三块，外加一条横幅：

- **外观** —— 大小（60~480px，带 很小 / 小 / 中 / 大 / 巨大 预设）、不透明度、投影开关与强度
- **行为** —— 速度（0~400 px/s，带 慢吞吞 / 正常 / 挺快 / 起飞 预设）、自动漫步开关、发呆时长上下限
- **窗口** —— 始终置顶、空白处鼠标穿透、**开机自启动**
- **互动** —— 定时提醒：选好分钟数（5 / 15 / 25 / 45 / 60）和提醒语，点「开始计时」，
  到点虫子会在头顶喊出那句话。菜单和托盘悬停提示显示的是触发时刻（见下方说明），
  实时跳秒的倒计时在这条横幅里看。挂在滚动区外面，不用滚就能看到。

顶部预览区会**实时演示**当前参数下的效果：虫子在里面来回走、到边缘转身并左右翻转，
尺寸按当前宽度等比缩放（右上角标着 `1:1` 或 `缩放 N%`）。
预览区背景是 `assets/preview-bg.mp4`（黄昏铁道），点「背景」按钮可以关掉，方便对着纯色底调参数。

拖动任意滑杆都是**即时生效**的，不用重启。主进程里只有一条 `applyConfig()` 写入路径，
右键菜单和控制选项都走它，所以两边的数值永远不会打架，`config.json` 也会同步落盘。

### 互动：定时提醒与气泡

控制选项底部的互动区是**事件触发**的：设定一个时长（10 秒 / 5 / 15 / 25 / 45 / 60 分钟）和一句提醒语
（默认「时间到了！」，最多 20 字），点「开始计时」。到点后虫子会在头顶冒出一句深色气泡，
停留 8 秒；横幅里每秒都在跳的倒计时、右键菜单的「定时提醒」子菜单、托盘悬停提示，都能随时
取消或重新计时。**10 秒档是专门留的快速验证档**——点完就能盯着看气泡，不用等 5 分钟。

### 为什么菜单里不显示「剩余 X 分 XX 秒」

Windows 的原生菜单打开之后就是一张**快照**：托盘菜单是资源管理器弹的，右键菜单是 popup
出来的原生窗口，都没有任何办法在开着的时候往里刷标签。「剩余 X 分 XX 秒」这种会跳字的文案
放进去，用户盯着它一秒秒不动，只会觉得坏了。所以菜单和托盘提示里显示的是一劳永逸的
**绝对触发时刻**（「⏱ 今天 18:45 触发」，跨天自动显示「明天」或具体日期），这个值永远不会过期；
要看实时倒计时，去控制选项的互动横幅（每秒刷新），或者干脆盯着虫子——到点它会喊。

右键菜单的「定时提醒」子菜单和控制选项共用同一套预设，点一下就开始计时，提醒语沿用控制选项
里设的那句，不用重复输入。

实现上有两个关键点：

- **存绝对时刻，不存"还剩多少秒"**：`config.json` 里记的是 `remindAt`（epoch 毫秒）。
  中途崩溃重启、甚至关机，到点仍然是原来那个时刻，不会被悄悄推后。
- **命令要排队**：渲染进程还在加载时 `webContents.send()` 会被静默丢弃。1 分钟的提醒很可能
  在 `did-finish-load` 之前就触发了，所以主进程维护一个 `pendingCmds` 队列，
  等 `sendEnv()` 时一起 flush 出去。

气泡本身画在虫子的 canvas 上，而不是另开一个 div——canvas 反正已经在跟着虫子移动了，
多画一个圆角矩形几乎零成本，而且天然不接鼠标事件，不会破坏点击穿透。
顶部预留了固定高度（`padTop`）而不是按需撑大 canvas，否则气泡出现的瞬间虫子会往下跳一下。
文字超出宽度时逐字砍掉、末尾补「…」。深色底白字：虫子是白身体，浅色气泡会和它糊在一起，
浅色底在深色壁纸上也会消失。

走 Electron 官方的 `app.setLoginItemSettings()`，在 Windows 上它写的就是
`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`。**重启电脑后生效**，不是下一次启动。

有个开发态的坑：`process.execPath` 是 `electron.exe`，不带项目根目录的话开机只会拉起一个空壳。
所以未打包时会把 `__dirname` 显式塞回参数里（`args: [__dirname]`），等价于 `electron .`；
打包版不需要这步，`isPackaged` 会区分开。副作用是**开发态下搬家了目录，自启动就失效**，
重新勾一次即可。

## 它是怎么动的

- **蠕动**：素材本身是一段 4.9 秒的循环动画。分析发现运动周期正好是 30 帧（1 秒），
  所以只取前 30 帧做循环，文件从 6.3MB 缩到 2MB。
- **左右移动**：素材里虫子头朝左。往右爬时把画面水平镜像（`scaleX(-1)`），
  往左爬时保持原样。
- **上下左右移动**：60Hz 的物理循环不断改变虫子的位置。
  随机挑一个目标点 → 平滑加速爬过去 → 到达后发呆 2~7 秒 → 再挑下一个目标。
  撞到屏幕边缘会反弹。

## 为什么不闪

第一版是"开一个小窗口，然后不停 `setPosition` 挪它"。在 Windows 上，透明窗口每移动一次
就要重新合成一次，必然出现明显的闪烁。

现在的做法：

- 窗口覆盖整个工作区，**位置永远不变**
- 窗口里只放一块"虫子大小"的 canvas（约 258×132），用 `translate3d` 移动它

窗口不动就没有重新合成的问题；`translate3d` 走 GPU 合成，移动丝滑。
顺带的好处是物理模拟和拖拽全部搬进了渲染进程，没有任何 IPC 延迟。

实测数据（埋点统计）：`draws/s = 30`（动画帧率精确）、每秒位移 55px、逐帧位移约 1px、
单帧画面变化量不超过虫体面积的 1.6%（若发生闪烁会接近 100%）。

## 自检

怀疑它又闪了、或者根本没动，可以拍几张照片让它自己算：

```bash
# 1) 连拍 6 张，间隔 700ms
python tools\capture.py -o D:\MiniPet\.tmp_burst -n 6 -g 700

# 2) 分析
python tools\verify.py D:\MiniPet\.tmp_burst --gap-ms 700
```

`verify.py` 拿连拍帧的中位数当背景（虫子一直在动，会被中位数抹掉），逐帧相减就能把虫子框出来，
然后报告三件事：逐帧包围盒、实测速度（跟 `speed` 对照）、以及**帧间变化率**——
平滑移动时只有边缘一圈在变（几个百分点），一旦整只虫子都在变（接近 100%）就是重绘/闪烁。

拍之前把会动的窗口挪开或最小化，否则运动检测会先抓到它们。
必要时用 `--roi x0,y0,x1,y1`（物理像素）手动圈定虫子所在区域；
**控制选项开着的时候它自己的预览区也在动，代码会先抓到那一大块**，所以要么关掉控制选项，要么用 `--roi` 把面板排除掉。

> 虫子是白身体，压在浅色界面上时和背景的灰度差很小。`--thresh` 默认 8；
> 如果虫子只剩"一圈描边"那么细，就是这个阈值太高了，往下调。
> 但也不能做开运算把虫身抹掉——`verify.py` 里为此专门跳过了一步。

`tools/capture.py` 是底层截屏。除了顺手调 `SetThreadExecutionState` 防止息屏（免得拍到冻结画面）之外，
它必须在**任何 GUI 调用之前**声明 DPI 感知：否则 Windows 会把屏幕尺寸按 96DPI 虚拟化报小
（本机物理 2560×1600 会报成 1707×1067），截出来只有左上角 2/3 的画面，
跑到屏幕右侧或下方的虫子会被整个漏掉。之前用 PowerShell 的 `CopyFromScreen` 就踩了这个坑——那个进程的
DPI 感知在启动时就被锁死了，运行里改不动，所以搬到了 Python。

## 素材处理

原始视频是黑白手绘风格，虫子是白色身体 + 黑色描边，背景是密集的排线纹理。
`tools/build_assets.py` 负责把虫子抠出来：

1. 亮度阈值 + 开运算 → 滤掉背景细排线，留下虫子这一块最大连通域
2. 闭运算 + 外轮廓填充 → 把描边内部的暗部（眼睛、皱纹）补回来
3. 沿暗色像素向外生长 → 把虫子自己的黑色描边吃进来，但不会蔓延到背景
4. 30 帧统一裁剪 → 输出 `assets/pet-sheet.png`（带 alpha 的精灵图）和 `assets/tray.png`

重新生成（改了参数或换了素材之后）：

```bash
python tools/build_assets.py
# 或指定别的视频
python tools/build_assets.py D:\视频素材\别的视频.mp4
```

依赖：`opencv-python`、`numpy`。

## 配置

首次启动会在根目录生成 `config.json`：

```json
{
  "petWidth": 150,       // 虫子显示宽度 (px)
  "speed": 55,           // 爬行速度 (px/s)
  "wander": true,        // 是否自动漫步
  "alwaysOnTop": true,   // 始终置顶
  "shadow": true,        // 投影，浅色壁纸上也能看清
  "shadowBlur": 12,
  "clickThrough": true,  // 透明区域鼠标穿透
  "focusable": false,    // 点虫子不抢走当前应用的焦点
  "idleMin": 2.0,        // 发呆时长下限 (秒)
  "idleMax": 7.0,        // 发呆时长上限 (秒)
  "opacity": 1,
  "autoStart": false,   // 开机自启动（走系统登录项）
  "remindAt": null,     // 定时提醒触发时刻 (epoch ms), null = 未设置
  "remindText": "时间到了！", // 到点时虫子在头顶喊出来的那句话
  "disableGpu": false    // 见下方说明
}
```

除了 `disableGpu` 和 `focusable` 需要重启，其余各项在控制选项里改完立刻生效。

### 关于 disableGpu 与 --no-sandbox

这台机器上 Chromium 的 GPU 进程在沙箱里会直接崩（`exit_code 0xC0000005`，
随后 `FATAL: GPU process isn't usable. Goodbye.`），用户看到的现象是"双击了但什么都没发生"。

处理方式是**启动器兜底**，而不是让人自己去关硬件加速：

- `main.js` 监听 `child-process-gone` / `render-process-gone`，发现 GPU 进程或渲染进程异常退出，
  就以退出码 **99** 退出
- `tools/launch.js` 看到 99，自动带 `--no-sandbox` 重新拉起一次（并打上 `--minipet-nosandbox`
  标记，避免无休止重试）

不在应用内用 `app.relaunch()` 是因为新进程会和旧进程的单实例锁抢时序，结果是被顶掉、什么都不剩。

`disableGpu` 默认 `false`（即用硬件加速）。如果画面出现异常，可以改成 `true` 强制走软件渲染；
2D 精灵图 + CSS transform 用软件渲染完全够用，实测渲染循环跑到 240Hz、动画稳定 30fps。
